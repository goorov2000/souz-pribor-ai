# Приёмка и соответствие ТЗ

Дата сверки: 03.11.2026. Основа — исходное трёхстраничное задание на AI-помощника товарных описаний, локальный код и сохранённые ответы. Приватный PDF не распространяется с репозиторием.

## Соответствие требованиям

| Раздел ТЗ | Что требуется | Реализация и границы |
| --- | --- | --- |
| 1. Цель | Локальный прототип B2B-карточки прибора | Форма/JSON → LLM → просмотр и экспорт; финальную проверку выполняет редактор |
| 2. Вход | Название, производитель, характеристики, описание по двум товарам | Поля поддержаны. В полученном PDF найден один JSON-пример DM 02; Testo выбран самостоятельно. Второй товар работодателя не предоставлен в проверенных материалах |
| 3.1 | Принимать JSON или веб-форму | Оба варианта; валидация клиента и сервера |
| 3.2–3.3 | Передавать в LLM API и формировать карточку | OpenAI Responses API, строгая структура, серверная сборка и одна коррекция |
| 3.4 | Удобное копирование результата | Просмотр, JSON, Markdown, копирование блоков и скачивание |
| 3.5 | Сообщать о недостатке данных | `needs_data`, известные факты, список пропусков и следующий шаг |
| 4.1 | SEO-заголовок до 70 символов | Для `draft` сервер проверяет 1–70 после удаления крайних пробелов |
| 4.2 | SEO-описание 800–1200 символов | Для `draft` границы обязательны; повторное нарушение не выдаётся как готовая карточка |
| 4.3 | Структурированные характеристики | Исходные значения сохраняются; извлечённые факты имеют цитаты; пропуски помечены |
| 4.4 | 3–5 поисковых запросов | Проверяются количество, непустые строки и уникальность |
| 4.5 | Commercial-блок | Отдельный видимый блок: аудитория и подтверждённая задача прибора |
| 5.1–5.2 | Разрешённый язык и API выбранной LLM | Python 3.11+, FastAPI/Pydantic/HTTPX; OpenAI, модель задаётся настройкой |
| 5.3 | Ключ вне кода | Окружение или игнорируемый `.env.local`; только сервер, без вывода в ошибки |
| 5.4 | Ошибки API, пустые поля, некорректный JSON | Технические проверки ошибок, сохранения ввода и возможности продолжить |
| 5.5 | Технические значения только из входа, без выдуманных свойств | Режим `enrich=false`. Проверки цитат и токенов ограничены; полная смысловая достоверность не доказана |
| 5.6 | «Данных нет» для отсутствующих характеристик | Пометки в таблице и `missing_fields`; конфликт требует уточнения |
| 6. Сдача | Код, README, два результата, промпты, решения, ограничения | Файлы в репозитории. Два полных примера есть, но только DM 02 взят из задания, Testo подобран отдельно |
| 7. Оценка | Корректность, промпт, полезность, обработка неполного входа, простой запуск | Техническая проверка и ручное чтение сохранённых результатов. Слепая оценка редакторами и статистическая надёжность не установлены |
| 8. Границы | Локальный MVP; CMS, БД и деплой не обязательны | Локальный сервер без CMS/БД/авторизации. Фактическое личное время 2–4 часа этой сверкой не подтверждено |
| 9. Формат | Репозиторий, короткое сообщение; при необходимости скриншоты | README и скриншоты включены. Отправка сопроводительного сообщения работодателю — отдельное действие |

В веб-форме поиск включён по умолчанию. Для буквальной проверки исходного задания его нужно снять; в API `enrich` по умолчанию `false`. Внешние источники — отдельно реализованное расширение, а не часть исходных данных работодателя.

Краткая справка `needs_data` до 600 символов — иной исход, не ослабление требований к `draft`. При бедном источнике длинный SEO-текст создавал бы повторы или домыслы.

## Техническая проверка

Команда из чистой копии:

```bash
uv run --frozen python scripts/check.py
```

Перед подготовкой публикации прошли 87 pytest, 13 изолированных браузерных и 9 сценариев через настоящий сервер. Публикуемый снимок проверяется той же командой локально и GitHub Actions; актуальный статус привязан к SHA коммита в [Actions](https://github.com/goorov2000/souz-pribor-ai/actions).

Проверены ввод и ограничения, длины, сохранение specs и нуля, цитаты, конфликты, обогащение, ошибки внешнего сервиса, пустой ответ, одна коррекция, экспорты и пользовательские сценарии. Внешний transport подменён. Платных запросов в обычном check нет, новая смысловая генерация — `NOT_RUN`.

Журналы, `source.json`, исходный архив, скриншоты и трассы находятся в артефакте соответствующего CI-запуска. [Границы проверок](check-workflow.md).

| Пример | Статус | Заголовок | Описание | Запросы | Данные |

| DM 02 | `draft` | 38 | 1116 | 4 | 4 исходных + 4 из названия/описания; 12 пропусков |
| Testo 805i | `draft` | 33 | 1134 | 4 | 7 исходных + 6 из названия/описания; 6 пропусков |
| Учебный ТД-01 | `needs_data` | — | Краткая справка | — | Недостаточно фактов для полной карточки |

Для базовых карточек повторно сверены входные specs, цитаты из названия/описания, длины, счётчики и совпадение JSON/Markdown с карточкой. Для web-строк проверены сохранённые HTTPS-источники и включение значения в цитату; новое скачивание источников в финальной сверке не выполнялось.

Примеры получены на более ранних снимках. После DM 02 менялись `cards.py` и `prompts.py`; после обычного Testo и ТД-01 — также `main.py`; после обогащённого Testo — `cards.py`. У последнего отдельно отмечен пересчёт экспорта без изменения значений и текстов. Provenance не переписывался для создания видимости нового живого прогона.

В DM 02 повторяются отдельные советы по подбору, в Testo встречаются исходные английские обозначения. Это пригодные заготовки с редакторской правкой, не утверждение о готовности без проверки человеком.

## История неудач и пределы вывода

Исторические исходы и ошибки сохранены в [evaluation/history/initial](../evaluation/history/initial/) и [evaluation/results](../evaluation/results/), включая summary. Непрошедший ответ и безопасная остановка не считаются успешно сформированной карточкой. Результаты разных фаз не складываются в единую оценку надёжности текущего снимка.

В ходе разработки обнаружены многословие на бедном источнике, необоснованные предложения уточнить известное, нарушения длины и риск переноса параметра соседней модели из общего руководства. Промпт и проверки уточнялись; отрицательные сценарии сохранены. Некоторые ошибки требуют смысловой оценки человека и не сводятся к совпадению чисел или подстрок.

Для дальнейшей приёмки полезен набор реальных товаров и независимые правки контент-менеджера, с сохранением всех попыток и разделением структурной и смысловой оценки. Сравнительный бенчмарк моделей и промышленный SLA не заявляются.
