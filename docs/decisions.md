# Решения и рабочие промпты

Сервер — FastAPI + Pydantic; HTTPX обращается напрямую к официальному `POST https://api.openai.com/v1/responses`, без SDK и скрытых повторов. Используются `reasoning.effort=none`, `max_output_tokens=3000`, `store=false`, `text.format={type:json_schema,name:product_card,strict:true,schema:…}`. Это формат Responses API. Ключ не передаётся на клиент.

Рабочий промпт — [app/prompts.py](../app/prompts.py), он импортируется сервером, поэтому документация не расходится с действующим текстом. Инструкции находятся в отдельном system-сообщении; сериализованные данные — в отдельном user-сообщении с меткой недоверенного источника. Промпт запрещает исполнять команды из полей, восстанавливать свойства аналогов и обещать неподтверждённые преимущества. Известные specs должны использоваться в описании с точной записью, уточняются только неизвестные свойства. Проверяемое `value` извлечённого факта входит в `quote`, название факта — короткий читаемый ярлык.

Модель создаёт SEO-текст, поисковые фразы, commercial-блок, извлечённые факты и предупреждения. Таблицу исходных specs и список пропусков строит сервер. Длины и числовые/технические обозначения проверяются кодом. Ошибочный результат не обрезается и не дополняется шаблоном до нужного объёма: модель получает краткий список нарушений и повторно создаёт ответ по исходнику. После второй неудачи возвращается ошибка. Коррекция не включает сырой невалидный ответ в новую инструкцию.

Строгая схема контролирует структуру, не истинность текста. Grounding-проверки — ограниченные эвристики: не определяют все свойства, не понимают все противоречия и не доказывают отсутствие галлюцинаций. Даже точная цитата требует смысловой проверки. В тестах проверяется граница сообщений и отказ сервера от новых чисел; это не сравнительный бенчмарк защиты модели от инъекций.

## Почему GPT-6 Luna

Выбор сделан по стоимости обычного тарифа и поддержке строгой JSON Schema с обработкой отказов. Для русского языка и товарных карточек сравнение с DeepSeek не проводилось; превосходство по связности текста или достоверности не заявляется. Проверены два результата Luna на конкретных входах.

На 02.11.2026 [страница GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) указывает Standard: $0.10 за 1 млн входных токенов, $0.50 за 1 млн выходных; модель поддерживает Structured Outputs и `none` для reasoning. [Руководство Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) описывает схему и отказы. Схема сама по себе не гарантирует истинность содержания.

Для сравнения стоимости: [официальные тарифы DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/) указывают Flash: $0.15–0.30 за 1 млн входных без кэша и $0.60–1.20 выходных; Pro: $0.66–1.32 и $1.98–3.96. Разброс связан с off-peak/peak, а не с замером качества. [JSON mode DeepSeek](https://api-docs.deepseek.com/guides/json_mode/) описывает получение JSON через `json_object`; соответствие нашей строгой схеме этим режимом не доказывается. DeepSeek в приложении не реализован.

Условная карточка: 2000 входных + 1000 выходных токенов, без кэша, повторов и рассуждения. Формула: `input / 1_000_000 × input_price + output / 1_000_000 × output_price`.

| Модель | Карточка, USD | 1000 карточек, USD |
| --- | ---: | ---: |
| GPT-6 Luna Standard | 0.0007 | 0.70 |
| DeepSeek Flash | 0.0009–0.0018 | 0.90–1.80 |
| DeepSeek Pro | 0.0033–0.0066 | 3.30–6.60 |

Это расчёт по тарифам, не эксперимент. Налоги, региональные надбавки, изменение цен, длина русского текста и повторные запросы могут изменить стоимость. Фактический usage живых прогонов записан в `examples/live-run.json`, отдельно от условной оценки.
